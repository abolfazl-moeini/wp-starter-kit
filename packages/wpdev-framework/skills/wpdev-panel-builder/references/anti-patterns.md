# Anti-patterns (common agent mistakes)

| # | Never do this | Do this instead | Why |
|---|--------------|-----------------|-----|
| 1 | Assume write target is `@examples/` | Write to host plugin per [consumer-plugin-layout.md](consumer-plugin-layout.md) | User's consumer plugin is primary |
| 2 | Build playground (`wpdev-pg-*`) panels | Use inlined skill recipes (optional `@examples/` only for deeper reading) | Playground removed from pack |
| 3 | Implement modal-create / tour / onboarding / custom action modal without user confirmation | Propose in Phase 2 and wait | Mandatory workflow |
| 4 | Call `wpdev_register_wizard()` or subclass `Setup_Wizard_Admin_Page` for a domain feature | See `wpdev-onboarding-ux/references/setup-wizard-constraint.md` | No generic wizard API |
| 5 | `modules/wpdev-products/` | Host plugin module + optional `@examples/products/` read | Layer separation |
| 6 | `wpdev_register_list_table()` for domain CRUD | `new My_List_Table()` in `List_Admin_Page::table()` + early `Ajax::register_list_table( $table_id, Class::class )` on module boot when `'ajax' => true` (where `$table_id` is `$table->get_table_id()`, e.g. `'productlisttable'`, not the admin page menu slug) | Products pattern; page construct alone does not register ids on `admin-ajax.php` |
| 7 | Guess `wpdev_register_*` signature | Read [api-cookbook.md](api-cookbook.md) + source | Prevents fatal |
| 8 | List table without `add_new` / empty state | Set `singular`, `plural`, `add_new` in constructor | § empty-states recipe |
| 9 | Plain-text status/type columns | Badge markup + Enum `classes()` map | Production UX |
| 10 | Invent tour `attachTo` selectors | Use page-level steps or confirm element exists | Broken tours |
| 11 | Ad-hoc `admin-ajax.php` outside `wpdev_register_ajax_handler()` | `wpdev_register_ajax_handler()` + `wp_send_json*` | Security + lifecycle |
| 12 | Read entire 500+ line class instead of recipe | Use specialist reference + `path:line` citation | Weak-agent friendly |
| 13 | `wpdev_path()` / `wpdev_url()` for host plugin files | `plugin_dir_path()` / `plugins_url()` | Framework paths only |
| 14 | Forget `Module_Loader::mark_loaded()` after manual register | Call `mark_loaded( $id )` after `require setup.php` | Soft-dep checks fail |
| 15 | Call cross-module/cross-domain API without check | `wpdev_module_is_loaded( 'module-or-host-id' )` or `function_exists()` / `class_exists()` | Soft dependency; `wpdev_example_is_loaded()` does **not** exist |
| 16 | `require` from `modules/*/src/` | Public `wpdev_*` facade only | API contract |
| 17 | Register widgets before `wpdev_load` | `wpdev_on_load()` or `add_action( 'wpdev_load', ... )` | Lifecycle |
| 18 | PHP under `inc/` | Host plugin `includes/` or module path | Legacy artifact |
| 19 | `@examples/wpdev-products/` folder | `@examples/products/` + module id `wpdev-products` | Naming rule |
| 20 | Ignore host plugin's existing folder layout | Match existing structure when present | Consumer ergonomics |
| 21 | Copy `WPDevFramework\Models\*` / `Database\*` namespaces into host plugin | Use host plugin namespaces + own autoloader | Module_Autoloader only covers framework modules |
| 22 | Only call `wpdev_register_table()` from a host plugin that boots on `plugins_loaded` priority 6 and assume the table exists | `new Host_Table()` in host `setup.php` / manager `init()`, override `$prefix`, call `install()` when needed | Table_Loader already booted; register-only is incomplete for late hosts |
| 23 | Forget to override `$prefix` on Table/Query/Schema and ship `wu_mything` by accident | Set the same host `$prefix` (+ `$name`) on Table, Query, and Schema; verify with `SHOW TABLES` | Framework default prefix is `wu` on all three engine classes |
| 24 | Require `@examples` or absolute personal machine paths to build a host panel | Use inlined skill snippets; optional submodule of wpdev-examples only for deeper reading | Skills must work on any machine |
| 25 | Re-hook `plugins_loaded` from a manager/component that boots on `wpdev_load`, or defer a registry entry needed during the current WPDev lifecycle to `init` | Hook `wpdev_load` (late priority if others must register first), or call the idempotent function directly; reserve `init` for intentional later deferral | `plugins_loaded` already fired; default light-Ajax can terminate before `init`; a too-late registry leaves “Form not available”, empty selects, or stuck loading widgets |
| 26 | `$.ajax` to a `wpdev_register_ajax_handler` action without a `nonce` field (and with only a `success` callback) | Send `nonce: window.wpdev_ajax.nonce` (dep `wpdev-ajax`), or for read-only previews register with `skip_nonce => true` + `capability_callback`; always add an `error` callback | Default `skip_nonce => false` → 403 `Invalid security token`; success-only JS freezes on “Loading …” forever |
| 27 | `wpdev_require_public_function( 'product' )` (or customer/site/email/…) | Framework basenames only (`ajax`, `date`, …); domain APIs load from `@examples/{slug}/setup.php` | Hybrid decoupling — unknown basenames trigger `_doing_it_wrong` |
| 28 | Register a script that calls `new Vue(...)` with only `array( 'jquery' )` deps | Declare `wpdev-vue` (plus `wpdev-block-ui` / `wpdev-sweet-alert` when used) | Script can run before Vue loads; app never mounts and the widget stays on its loading placeholder |
| 29 | Settings section `icon` => core-only `dashicons-megaphone` without thinking | Prefer `dashicons-wpdev-*`; helper may prepend `dashicons` for core slugs | Left-nav uses class as-is; WPDev font glyphs look correct in settings chrome |
